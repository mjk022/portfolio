# 웹 데이터 수집(크롤링) 코드 모음

> 분석에 필요한 데이터를 웹에서 직접 모으기 위해 작성한 코드들입니다. 웹페이지의 종류에 따라 서로 다른 네 가지 수집 방법을 사용했습니다.

## 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 언제 | 2023 (주로 캡스톤 디자인 진행 중) |
| 누가 | 개인 작성 |
| 무엇을 | 앱 리뷰, 유튜브 댓글, 공연 정보·이미지 수집 |
| 왜 | 공개 데이터셋에는 없는 리뷰·댓글·공연 정보를 분석에 쓰기 위해 |
| 어떻게 | 페이지 특성에 맞춰 BeautifulSoup, Selenium, OCR, 공식 API 중 선택 |
| 결과 | 인터파크 수집 데이터가 [추천시스템](../추천시스템) 프로젝트의 기반 데이터로 사용됨 |

## 1. 왜 여러 방법이 필요했나

"웹에서 데이터 가져오기"라도 웹페이지가 만들어지는 방식에 따라 방법이 달라집니다.

| 방식 | 언제 쓰나 | 쉽게 말하면 |
|---|---|---|
| BeautifulSoup | 페이지 내용이 처음부터 다 들어 있는 정적 페이지 | 페이지 코드를 한 번 받아 필요한 부분만 골라냄 |
| Selenium | 스크롤하거나 버튼을 눌러야 내용이 더 나오는 동적 페이지 | 실제 브라우저를 띄워 사람처럼 스크롤·클릭함 |
| OCR (Tesseract) | 글자가 이미지로만 제공될 때 | 이미지 속 글자를 읽어 텍스트로 바꿈 |
| 공식 API | 서비스가 데이터 제공 창구를 열어 둔 경우 | 정해진 규칙으로 요청하면 정리된 데이터를 받음 |

## 2. 무엇을 수집했나

| 파일 | 대상 | 방식 | 수집 내용 |
|---|---|---|---|
| `1)_크롤링+스크레이핑_.ipynb` | Python 공식 매뉴얼 | BeautifulSoup | 링크를 따라가며 문서 전체를 자동으로 다운로드 |
| `구글플레이스토어_리뷰.ipynb` | Google Play 앱 페이지 | Selenium | 스크롤과 "더보기" 클릭을 반복하며 앱 리뷰 수집 |
| `유튜브_댓글.ipynb` | YouTube 영상 | Selenium | 끝까지 스크롤하며 댓글 수집 |
| `유튜브_댓글_API이용.ipynb` | YouTube Data API | 공식 API | 댓글과 답글, 작성일, 좋아요 수 |
| `인터파크_월간랭킹뮤지컬_배우.ipynb` | 인터파크 티켓 랭킹 | Selenium | 랭킹 상위 뮤지컬의 출연 배우 |
| `인터파크_월간랭킹연극_공연상세 이미지.ipynb` | 인터파크 공연 상세 | Selenium + OCR | 줄거리가 담긴 상세 이미지를 받아 글자 추출 |

## 3. 결과와 배운 점

유튜브 댓글은 Selenium과 공식 API 두 가지로 모두 수집해 봤습니다. Selenium은 사이트 화면 구조가 바뀌면 코드가 쉽게 깨졌지만, 공식 API는 구조 변화와 상관없이 안정적으로 동작했고 서비스 약관 측면에서도 적절했습니다. 공식 API가 있다면 그것을 먼저 쓰는 것이 좋다는 것을 배웠습니다.

인터파크 공연 줄거리는 이미지로만 제공되어 OCR이 필요했습니다. 이렇게 모은 데이터는 [추천시스템](../추천시스템) 프로젝트에서 줄거리 기반 추천에 사용되었습니다.

## 참고

- 유튜브 API 키는 코드에 넣지 않고 환경변수 `YOUTUBE_API_KEY`에서 읽습니다.
- 수집한 댓글과 리뷰에는 작성자 정보가 포함되어 있어, 노트북의 실행 결과는 지우고 코드만 올렸습니다.
